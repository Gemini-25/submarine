# M2 계획 · 8대 계통

2026-10-27 · 자세한 설계(에이전트용, 영어)는 [M2-design.md](M2-design.md). 결정은 [DECISIONS.md](../DECISIONS.md)의 'M2' 절.

## 목표

SPEC 12절 M2: 고장 26종, 도구, 응급과 정식 수리, 예비 부품 사물함, 매뉴얼, 계산 도구.
완료 기준은 "계통마다 대표 고장 2종 이상을 진단하고 수리할 수 있다"입니다. 항법과 케이블 장비는 단독 훈련으로 확인하고, 임무 연쇄는 M3에서 봅니다.

## 구조

- **범용 장치 엔진.**
  - 손이 닿는 것(볼트, 덮개, 소켓, 밸브, 조절 손잡이, 작업, 레버, 만져 보기)을 종류 일곱 개와 만져 보기 하나로 나눕니다.
  - 각 장치는 데이터(`data/fixtures/*.json`)로 정의합니다. 전제 조건, 거부 사유, 위험, 효과를 적습니다. 판정 순서는 M1과 똑같습니다.
  - 조건은 시나리오 assert 문법을 그대로 씁니다.
  - 고장 여부나 상황판 값처럼 '정답'을 읽는 조건은 검증기가 막습니다. 판정은 늘 물리 상태로만 합니다.
- **상태는 부품의 속성으로만.** 새 계통의 상태(증기 압력, 트림, 자이로 등)는 데이터로 정의한 '상태 부품'의 속성에 둡니다. 저장, 해시, 조회가 저절로 따라옵니다.
- **모듈은 데이터가 켭니다.** 상태 부품이 없으면 그 계통 규칙은 아무것도 하지 않습니다. 그래서 M0와 M1의 기준 해시는 그대로 유지됩니다.
- **숨은 결함.** 볼트 조이는 순서를 교범 절차의 순서와 비교합니다(현창 1-4-2-5-3-6, 증기 플랜지 1-3-2-4). 어기면 고친 것처럼 보이지만 늦게 증상이 나옵니다.
- **응급 수리는 수명이 있습니다.**
  - 팬 손으로 돌리기, 베어링 기름칠, 망치로 밸브 풀기, 이음 감기, 접점 조이기가 여기에 해당합니다.
  - 수명이 다하면 고장이 돌아옵니다.
- **도구는 들고 다니는 물건.**
  - 해치 격벽에 도구판을 두고, 허리띠는 5칸입니다.
  - 1은 빈손, 2~6은 허리띠 칸입니다. 처음 허리띠는 M1 도구 다섯 개 그대로입니다.
  - 감전되거나 물이 뿜어지면 든 도구를 떨어뜨리고, 10도 넘게 기울면 바닥의 도구가 굴러갑니다.
- **관찰.**
  - 단서(소리, 냄새, 보이는 것, 손에 느껴지는 것)와 계기 읽기는 시뮬레이션이 계산합니다. 상태로 저장하지 않습니다.
  - 전압계 외에 비중계, 청진기, 저항 측정 브리지, 램프 시험을 둡니다.
  - 만져 보기는 위험할 수 있어서 명령입니다. 화면에는 "뜨겁다" 같은 말로만 나옵니다.
- **위험 추가:** 화상(증기는 데임)과 물 분출.

## 지킬 것 (모든 작업 묶음)

1. M0·M1의 기준 해시는 정해진 때에만 다시 만듭니다. 그때는 어떤 키가 왜 바뀌는지 미리 적습니다.
2. `SimWorld`에 새 필드를 만들지 않습니다. 새 상태는 부품 속성에만 둡니다.
3. 새 규칙은 기본 상태에서 정확히 아무것도 바꾸지 않습니다.
4. 커밋마다 `dotnet test`와 Godot 확인이 통과합니다.

| --- | --- | --- |
| 1 | WP0 기준 해시 정책과 확인 도구 | 본선 |

| 2 | WP1 장치 엔진과 퓨즈 소켓 이식 | 본선 |
| 2 | WP6 Godot 배치(새 장비 자리, 손 닿는지와 작업 시점 검사) | 병렬 세션 |
| 3 | WP2 도구판과 허리띠, 위험 · WP3 부품 공통 메커니즘 · WP4 관찰과 측정, 교범 렌더러 | 본선 |

| 5 | 1차 계통 고장: WP8 배전반, WP9 공기, WP10 배수, WP11 동력, WP12 선체, WP13 감각, WP14 항법, WP15 케이블 | 병렬 세션 여러 개 |
| 6 | WP16 완료 기준 점검(1차 고장 16종을 자동 플레이어가 상황판과 단서만 보고 해결) | 본선 |
| 7 | 2차 계통 고장: WP17~20 (접점, 화로, 역류 밸브, 밸러스트와 기울기, 증기, 현창, 케이블 챔버, 상황판 배선, 탐조등, 계기 영점) · WP22 Godot 계산 도구 | 병렬 세션 |
| 8 | WP23 마무리: 고장 26종 전체 진단과 해결 가능성, 기준 해시, 보고서, 플레이 테스트 요청 | 본선 |

설계안의 작업 추정은 합계 63.5시간입니다. 처음 말씀드린 12~20시간보다 큽니다. 고장 26종의 증상과 수리, 교범 30여 쪽, 계산 도구 네 가지가 모두 들어가기 때문입니다. 병렬 세션으로 달력 시간을 줄입니다. 6단계 점검에서 일정이 밀리면, 2차 고장의 Godot 장비와 계산 도구 다듬기는 M3로 넘길 수 있습니다. 그 경우에도 시뮬레이션, 수리, 테스트, 교범은 M2에 다 넣습니다.

## 플레이 테스트 (M2 끝에 몰아서)

- 훈련마다 교범만 보고 진단할 수 있는지
- 손동작의 느낌, 허리띠 칸 수의 번거로움
- 소리로 고장을 가를 수 있는지
- 계산 도구, 기울기의 느낌, 교범 찾아보기
- 공기와 축전지가 줄어드는 속도 (SPEC 15절에서 M2까지 정하기로 한 것)
