# M2 보고서 · 8대 계통

2026-10-30 · 브랜치 `claude/dazzling-clarke-m2eohe`. 계획은 [docs/plans/M2.md](../plans/M2.md), 작업 묶음별 설계는 [M2-design.md](../plans/M2-design.md), 결정은 [DECISIONS.md](../DECISIONS.md)의 M2 절에 있다.

## 1. 요약

- **완료 기준을 채웠다.** SPEC 12절의 M2 완료 기준은 "계통마다 대표 고장 2종 이상을 진단하고 수리할 수 있다"이다. 여덟 계통의 고장 26종이 모두 들어갔고, 훈련 열여섯이 계통마다 둘 이상의 고장을 다룬다(3절). 항법과 케이블 장비는 단독 훈련으로 확인했다.
- **자동 플레이어가 교범만 보고 훈련 열여섯을 모두 푼다.** 규칙 기반 자동 플레이어(DrillSolver)는 상황판, 계기, 단서처럼 사람이 볼 수 있는 값만 읽고, 교범 진단 표를 옮긴 진단 자료로 원인을 좁힌다. 사람 속도로 손을 움직이며, 다치지 않고 끝낸다.
- **같은 풀이를 Godot에서 손동작으로 다시 한다.** 걸음마다 실제로 조준하고 끌고 돌려서, 시뮬레이션만 돌린 기록과 걸음 하나하나, 1분마다의 해시, 마지막 해시까지 같다.
- **진단 가능성 행렬**: 고장 26종 모두가 진단 자료의 판정으로 이어지고, 증상이 비슷한 짝끼리도 교범의 확인 절차로 갈린다.
- **교범 40쪽**과 그림, **공구판 17종과 공구띠**, **예비품 사물함 세 곳**, **계산 도구 네 가지**(탁상 계산기, 계산자, 노모그램, 저항 브리지)가 들어갔다.
- **기준 해시**: M0·M1의 키는 WP0에서 한 번 다시 만든 뒤로 바이트 하나 바뀌지 않았다. M2 마감 때의 데이터를 얼려 M2 키 36개를 더했다(6절).
- **사람 확인이 남았다.** 손맛, 소리, 교범만으로 진단할 수 있는지는 사람이 해 봐야 안다. 8절의 플레이 테스트를 부탁드린다.

### 교범 (`data/manual/`)

- 40쪽. 00~13쪽은 배 전체의 일반 쪽이고, 20~45쪽은 계통마다 수리 절차다. 계통 탭으로 한 계통만 골라 본다.
- 진단 표(03~05쪽)는 증상에서 확인 절차를 거쳐 원인과 절차 쪽으로 이어진다. 솔버가 읽는 진단 자료는 이 표를 옮긴 것이고, 시험이 표지와 자료가 맞는지 본다.
- 그림(WP26): 위치도, 부품 그림, 절차 순서 띠, 계통도. 장면 그림은 게임 장면을 찍어 먹선으로 바꾸고, 계통도는 데이터에서 그린다. 그림 안에는 번호만 두고 설명은 캡션에 쓴다. 그림이 장면, 절차, 데이터와 어긋나면 `figures` 확인 묶음이 실패한다.

## 4. 훈련 해 보기

1. Godot에서 `game/project.godot`를 열고 빌드한 뒤 F5로 실행한다. 명령줄이면 `"$GODOT" --path game`.
2. 지시서 화면 왼쪽의 '훈련 고르기'에서 훈련을 고른다. 지시서를 읽고 Enter를 누르면 근무가 시작된다.
3. 막히면 Tab으로 교범을 편다. 상황판(02쪽) → 진단 표(03~05쪽) → 절차 쪽 순서로 본다.
4. 결과 화면에서 R을 누르면 지시서 화면으로 돌아간다.

특정 훈련으로 바로 시작하려면 `"$GODOT" --path game -- --mission=m2-hull-b`처럼 준다. 자동 플레이어가 손동작으로 푸는 모습은 `tools/godot-check.sh drill:m2-hull-b`로 돌려 볼 수 있다(헤드리스).

## 6. 기준 해시

- M0·M1 묶음(`golden-data`, `golden-scenarios`, `golden-hand`, 위기 한 판, 리플레이 둘)의 키 25개는 WP0에서 한 번 다시 만든 뒤로 그대로다. M2의 새 규칙은 상태 부품이 없으면 아무것도 하지 않기 때문이다.
- M2 묶음(키 앞에 `m2/`): M2 마감 때의 데이터(`golden-data-m2/`, 교범 빼고), 그때의 시나리오 열아홉(`golden-scenarios-m2/`), 훈련 열여섯의 풀이 기록(`golden-drills-m2/`), 위기 한 판. 키 36개를 더했다.
- 얼린 기록을 얼린 데이터에서 솔버 없이 다시 내면 훈련이 성공으로 끝나고, 해시가 기록에 적힌 것과 같다.
- 이제부터 튜닝은 살아 있는 훈련 기록(`drill-logs/`)만 바꾼다. 기준 해시 키는 규칙을 바꿀 때만 움직이고, 그때는 작업 묶음이 미리 키를 밝힌다.

## 7. 알려진 문제와 M3로 넘긴 것

- **무작위 고장**: M2에서 더한 고장은 저절로 생기지 않는다(마모로 생기는 것만). 발생률은 M3에서 임무와 함께 맞춘다.
- **수심**: 훈련에서는 수심을 고정한다. 수심이 움직이는 것은 M3(항해)부터다.
- **2차 장비의 표현 다듬기**: 2차 고장 장비의 작업 시점, 소리, 계산 도구의 손맛 다듬기는 M3로 넘길 수 있게 정했다(DECISIONS WP16). 지금도 모두 손동작으로 끝까지 할 수 있다.
- **자기 나침반**: 책상 위 읽음 창의 숫자로만 읽는다. 나침반 통(`gadget.compass`)은 눌러도 이름만 뜨고 카드가 돌지 않는다.
- **임무 성공 조건**: 분기함에 물기가 갇힌 채(trapped) 끝나도 훈련은 성공이다. 솔버 시험만 이를 본다. 임무 조건에 넣을지는 M3에서 정한다.
- **케이블 단자의 저항**: 저항 브리지의 마지막 리드는 M3의 실제 케이블 저항을 기다린다.
- **실제 GPU**: 성능과 그림자는 소프트웨어 렌더러로만 봤다. 실제 기기의 Forward+에서 한 번 봐야 한다.
- **교범 그림의 빈자리**: 22쪽 축압기의 이음 감기와 개스킷 교체 순서 띠, 21·38·42·43쪽 가르기의 비교 그림, 작은 부품(45쪽 모세관, 39쪽 진공관)을 가까이 찍은 칸, 08쪽 전압계와 비중계를 손에 든 모습이 아직 없다. 지시선 배치처럼 읽기 쉬움에 관한 다듬기와 함께 M3의 아트 손질로 넘긴다([m2-wp26.md](m2-wp26.md)의 '남은 일'). 그림이 틀리게 가르치는 곳은 없다.
- **Godot 확인 시간**: 전체가 예산(4분)에 가깝다. 늘어나면 `drills`와 겹치는 계통별 `drill-<계통>` 묶음을 기본 실행에서 뺀다.

## 8. 플레이 테스트 확인 목록

훈련마다 교범과 상황판만 보고, 자동 플레이어의 진단 자료를 모르는 사람이 해 보는 것이 좋습니다. 막힌 곳은 쪽 번호와 줄을 적어 주시면 고치기 쉽습니다.

### 진단과 교범

1. 진단 표(03~05쪽)의 '확인' 열만으로 원인을 하나로 좁힐 수 있는가.
2. 차례와 계통 탭으로 쪽을 찾을 수 있는가. 진단 표에서 절차 쪽까지 몇 번 넘기는가.
3. 그림이 도움이 되는가. 그림의 번호와 캡션, 본문 단계가 서로 잘 맞는가. 위치도만 보고 그 장비를 배 안에서 찾을 수 있는가. 비교 그림 A·B의 차이(퓨즈, 펌프 전류 계기, 흡수통 지시약 창, 종이 리본, 라이닝)가 한눈에 보이는가. 짙은 음영이 너무 무겁지 않은가. 칸이 여덟 넘는 순서 띠에서 붉은 고리와 화살표가 무엇을 가리키는지 알 수 있는가. 그림 아래 설명의 글씨 크기와 크게 보기가 편한가.
4. 교범의 문장이 정비 교범답게 딱딱하면서도 자연스럽게 읽히는가.

### 훈련별

5. **동력 A**: 셀 여섯을 전압계로 재는 일이 번거롭지 않은가. 전령기를 내렸다가 되돌리는 것을 잊지 않는가.
6. **동력 B**: 축압기를 고친 뒤 선내 김이 걷히기를 기다렸다가 분기함을 말리는가.
7. **배전반 A, B**: 탄 배선과 누전을 어느 순서로 고치는가. 철사 퓨즈를 알아보는가. 접점 부식을 칼날 스위치 양쪽 전압 차로 찾는가.
8. **공기 A, B**: 팬을 고친 뒤 흡수통 지시약을 보러 가는가, 이산화탄소 추세로 알아채는가. 양초를 켜 보고 화로 막힘을 아는가.
9. **배수 A, B**: 막힘과 베어링이 겹쳤을 때 소리로 가르는가. 3분 식히기를 기다리는가, 데는가. 역류 방지 밸브를 의심하게 되는가.
10. **밸러스트**: 경사계와 유리관으로 어느 탱크가 문제인지 아는가. 침투유를 기다리는 동안 무엇을 하는가.
11. **선체 A, B**: 축 패킹과 리벳 누수를 소리 자리로 가르는가. 현창 볼트 조이는 순서를 지키는가. 케이블 챔버 우물에 내려가고 올라오는 것이 자연스러운가.
12. **감각 A, B**: 벨은 울리는데 등이 꺼진 것을 알아채는가. 엇갈린 배선과 계기 영점을 손에 든 전압계로 찾는가.
13. **항법**: 자이로가 자리 잡는 5분 동안 무엇을 하는가. 자차표 셈이 어려운가.
14. **케이블**: 지시서의 시험 키 점검을 하는가. 멈춤쇠를 먼저 거는가.
15. **시운전**: 고장이 겹칠 때 무엇부터 손대는가.

### 손과 몸, 화면

16. 볼트 돌리기, 스위치 끌기, 수동 펌프 젓기 같은 손동작의 느낌. 작업 시점(32곳)의 각도. 특히 축, 펌프, 축전지, 통신 책상, 새로 높인 '전기 예비품' 벽장.
17. 공구띠 다섯 칸 때문에 공구판을 오가는 일이 성가신가. 도구 17종이 이름표 없이도 갈리는가(특히 줄, 드라이버, 쑤시개, 청진기, 비중계처럼 가늘고 긴 것). 빈 윤곽만 보고 무엇이 빠졌는지 아는가. 헌 부품이 헌 것으로 보이는가.
18. 단서 소리(쉿 소리, 자갈 소리, 진공관 잡음 등)가 들리는가. 지금 소리는 자리표시 합성음이다.
19. 기울기: 화면이 기우는 정도, 비탈 걸음, 구르는 도구가 자연스러운가.
20. 계산 도구 네 가지를 교범 09쪽만 보고 쓸 수 있는가. 글씨가 읽히는가.
21. 공기와 축전지가 줄어드는 속도에서 긴장감이 적당한가(SPEC 15절의 열린 질문).

### 배치와 화면 (앞선 보고서에서 미뤄 둔 것)

22. 증기 축압기는 해치를 닫아야 손이 닿는다. 정식 수리 중 해치가 닫혀 빌지가 갈리는 것이 괜찮은가([m2-layout.md](m2-layout.md)).
23. 조종석이 축전지 우물 우현 가장자리를 덮어 6번 셀이 좌현에서만 잘 보인다. 조종석을 옮길지.
24. 실내등 밝기 곡선(지금은 제곱), 분위기와 색, 경고등 연출, 선체 단면([art-kit.md](art-kit.md)).
25. 실제 GPU에서의 성능과 그림자.
