## 구현한 것

`sim/`(DeepLine.Sim)은 Godot을 참조하지 않는 순수 .NET 8 라이브러리입니다. SPEC 3절의 `ISimulation`(Load, Apply, Step, Snapshot, DrainEvents, Tick, StateHash)을 구현했습니다.

| 계통 | 내용 |
| --- | --- |
| 동력 | 6셀 축전지(셀별 charge, health, 온도, 점퍼). 버스 전압은 셀별 f(charge) × health 배율의 합. 열화 셀은 용량이 작아 먼저 비고 뜨거워진다. 점퍼하지 않은 죽은 셀은 버스 전압을 크게 깎는다. 빈 셀의 몫은 다른 셀이 진다 |
| 배전반 | C1~C8, 칼날 스위치, 퓨즈(정격 초과 2초에 단선), 분기함 습기에 따른 누전. 저항성 부하와 전동기 부하를 나눈다. 정상 부하로는 어떤 전압에서도 퓨즈가 끊기지 않는다는 데이터 검증 규칙 |
| 장비 | SPEC 4절 표의 14종. 최소 전압, 소음, 발열, 과열 정지(펌프), 펄스(소나), 스로틀(추진) |
| 침수와 배수 | 누수 q = k·a·√d, 빌지 두 칸(해치로 나뉨), 바닥 위 물의 퍼짐, 전동 펌프(흡입구 막힘, 베어링, 역류 방지 밸브), 수동 펌프, 셀 잠김 |
| 선체 | 누수 지점 20곳, 응력과 integrity, 응급 패치 내구도와 재발, 선체 붕괴 |
| 공기 | CO2, O2, 염소, 수소. 흡수통과 포화, 산소 양초, 잠긴 셀의 염소와 수소, 팬의 희석 |
| 열과 마모 | 장비 온도, 과열 시 wear 3배, wear → 상태 단계, wear → 부품 상태 값(베어링 저항), wear가 임계를 넘으면 고장 주입 |
| 소음 | 현재 소음 N과 누적 소음 A. 장비 소음, 행동 소음(명령마다 크기와 지속 시간) |
| 상황판 | 8계통 표시등, 계기 8개, 경보 벨, 구역 경고등(비상 급전). 모두 센서 값 한 벌만 읽는다 |
| 몸 상태와 실패 | CO2, O2, 염소 단계. 의식 상실, 폭발, 선체 붕괴, 침몰(대리 기준)은 임무 실패 |
| 고장 주입 | M0 범위 9종. 부품 상태 값과 상태 하한만 바꾼다. 무작위 고장(시드 고정, 수심과 wear 배율) |
| 저장 | 전체 상태 저장과 복원(시드, 시작 설정, 대기 명령, 꺼내지 않은 사건 포함) |

`data/`에는 `tuning.json`, `circuits.json`, `devices.json`, `parts.json`, `faults.json`, `hull.json`이 있습니다. 모르는 필드와 빠진 필수 키는 로드 오류입니다.

명세에 없거나 명세와 다르게 정한 것은 전부 [docs/DECISIONS.md](../DECISIONS.md)에 있습니다. 큰 것만 추리면 다음과 같습니다.

- 빌지를 해치 기준 두 칸으로 나눔 (REVIEW 질문 1)
- 잠긴 셀에서 수소 발생 (REVIEW 질문 2)
- 누적 소음을 dA/dt = (N − A)/τ, τ = 90초로 정규화 (SPEC 식의 시간 단위가 없어서)
- 버스 전압 식에 셀 health를 넣고, 장비 부하 종류를 둠
- faults.json의 `effects` 식을 없애고, 증상은 계통 코드가 부품 상태 값을 읽어 만듦

## 실행 방법

.NET 8 SDK가 필요합니다. Windows에서는 Godot 4.7.2 .NET이 요구하는 SDK와 같습니다.

```sh
dotnet test
dotnet run --project tools/DeepLine.SimCli -- validate
dotnet run --project tools/DeepLine.SimCli -- run sim.tests/scenarios/10-wtr01-clogged-intake-floods-battery.json --every 1200
dotnet run --project tools/DeepLine.SimCli -- run sim.tests/scenarios/13-hatch-closed-protects-battery.json --paths bilge.fwd.water,bilge.aft.water,zone.aft.water,battery.submerged --csv out.csv
```

## 플레이 방법

M0에는 화면이 없습니다. 개발 도구 `tools/DeepLine.SimCli`로 시나리오를 돌려 기대값 판정, 주요 사건, 시계열(CSV)을 볼 수 있습니다. 시나리오를 직접 만들어 보시려면 `sim.tests/scenarios/`의 파일을 복사해 `inject`(고장), `commands`(명령), `expect`(기대값)를 고치면 됩니다. 문법은 `sim/Faults/Assertion.cs` 주석에 있고, 볼 수 있는 값의 이름은 `sim/Core/SimQuery.cs`에 있습니다.

## 알려진 문제

- **SPEC 13절의 예시 시나리오(HUL-03)는 쓰지 않았습니다.** HUL-03은 M2 범위이고, 명세 수치로 성립하지 않습니다(축전지 −5%에 평균 720W가 필요하고, 20초 안에 바닥 위로 물이 차려면 약 90cm² 누수가 필요). 같은 연쇄(누수 → 펌프 → 축전지)는 시나리오 09가 HUL-01로 검사합니다.
- **수치는 명세 값을 그대로 썼고, 근무 임무 길이에 비해 느슨합니다.** 공기 고장은 20분에 첫 증상, 축전지는 펌프를 30분 상시 돌려도 22.5%만 씁니다. 테스트를 맞추려고 바꾸지 않았습니다. M1 플레이 테스트에서 함께 맞추겠습니다(REVIEW '나중에 정해도 되는 질문').
- **습기의 원천이 아직 없습니다.** 누전(ELC-03)은 고장 주입으로만 생깁니다. 침수와 증기 누설(PWR-03)에서 습기가 오르는 규칙은 M2에서 넣습니다.
- **침몰 실패는 바닥 위 물 6,000L 초과라는 대리 기준입니다.** M2 부력 모델에서 바꿉니다.
- **플랫폼 간 결정론은 Linux x64에서만 확인했습니다.** 기준 해시가 Windows에서도 맞는지는 아직 모릅니다(아래 확인 요청).
- **GameData의 정의 객체는 공개 setter가 있습니다.** 한 데이터를 여러 시뮬레이션이 같이 쓸 때 도중에 고치면 안 됩니다. 지금은 테스트만 이것을 씁니다.
- **Godot 쪽은 아직 아무것도 없습니다.** 이 환경에서는 Godot 실행 파일을 받을 수 없어서 M1의 헤드리스 스모크 테스트를 돌릴 방법이 아직 없습니다(REVIEW 질문 4).
