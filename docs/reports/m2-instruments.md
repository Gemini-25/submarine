## 요약

SPEC 7절 '선내 계산 도구' 네 가지의 역학을 순수 .NET 8 라이브러리 `instruments/DeepLine.Instruments`로 만들었습니다. Godot과 sim은 참조하지 않습니다. sim의 BannedSymbols 밖이라 로그 눈금을 씁니다. 화면 표시 전용 상태라서 재생과 저장에는 들어가지 않습니다(M2 설계 'Calculation tools as in-world objects').

| 완료 기준 (M2 설계 WP21) | 결과 |
| --- | --- |
| 계산기 곱셈과 나눗셈이 정확 | 123456 × 789 = 97406784, 97406784 ÷ 789 = 123456 나머지 0. 레지스터 끝자리까지 곱 5건, 소수 자리가 있는 나눗셈 6건이 정확합니다. 나눗셈은 자리마다 벨이 한 번씩 울립니다 |
| 계산자 0.5% 이내 | 1~10 격자(68 × 68)에서 C·D 곱셈, 나눗셈, CI 곱셈이 모두 0.5% 안에 듭니다. 입력과 결과를 모두 눈금 한 칸의 1/5로 둥글게 읽은 값입니다 |
| 노모그램 2% 이내 | 세 장 모두 공식과 2% 안에서 맞습니다. 자 끝을 위아래로 1/3mm씩 어긋나게 놓은 최악의 경우 누수 1.37%, 축전지 1.41%, 잠김 1.45%입니다(도표 높이 0.6m 기준) |
| 브리지가 다이얼 한 칸 안에서 평형 | 0.5Ω부터 9.9GΩ까지 55가지 저항에서 설정 ≤ Rx < 설정 + 한 칸입니다 |
| `dotnet test` 통과 | 루트에서 인자 없이 돌려 세 시험 프로젝트가 모두 통과합니다. 계산 도구 93개, sim 255개, 소리 139개 |

바꾼 기존 파일은 `DeepLine.sln` 하나입니다(두 프로젝트를 `instruments` 솔루션 폴더에 넣었습니다). 시험은 지시대로 `sim.tests`가 아니라 `instruments/DeepLine.Instruments.Tests`에 따로 두었습니다. 설계안 WP21의 파일 목록에는 `sim.tests/InstrumentTests.cs`가 적혀 있지만, 본선이 sim.tests를 고치고 있어 충돌을 피했습니다.

## API 요약

### DeskCalculator · 바퀴식 탁상 계산기

오드너식 기계를 본떴습니다. 설정 8자리, 결과 13자리, 회전 수 8자리이고 캐리지는 0~5자리를 오갑니다.

| 멤버 | 하는 일 |
| --- | --- |
| `Lever(place)`, `SetLever(place, digit)`, `StepLever(place, steps)` | 설정 레버. place 0이 일의 자리. `StepLever`는 멈춤 칸 단위로 움직이고 0과 9에서 멈춥니다 |
| `SetNumber(n)`, `Setting` | 설정 레버를 한꺼번에 놓고 읽기 |
| `Carriage`, `ShiftUp()`, `ShiftDown()`, `ShiftTo(place)` | 캐리지 자리. 끝에서는 움직이지 않고 false |
| `Turn(forward)`, `Forward()`, `Back()` | 손잡이 한 바퀴. 결과에 설정 × 10^캐리지를 더하거나 빼고, 회전 수에 ±10^캐리지를 셉니다. 벨이 울리면 true |
| `Result`, `ResultDigit(place)` | 결과 창. 벨이 울린 뒤에는 13자리 보수(9999…)가 보입니다 |
| `Counter`, `CounterNegative`, `CounterDigit(place)` | 회전 수 창의 크기와 빨간 숫자 여부. 뒤로 돈 수가 더 많으면 빨간 숫자 |
| `event Bell`, `BellCount` | 빼서 결과가 0 아래로 내려갈 때 |
| `ClearResult()`, `ClearCounter()`, `ClearSetting()`, `ClearAll()` | 지우기 손잡이 |
| `CalculatorDrill.Multiply(c, a, b)` | a를 놓고, b의 자리마다 캐리지를 옮겨 그 숫자만큼 앞으로 돌립니다. 밟은 걸음 목록을 돌려줍니다 |
| `CalculatorDrill.Divide(c, dividend, divisor, decimals)` | 피제수를 결과 창에 올리고, 맨 윗자리부터 벨이 울릴 때까지 뒤로 돌리고, 앞으로 한 번 되돌리고, 캐리지를 내립니다. 몫 × 10^decimals는 회전 수 창(빨간 숫자), 나머지는 결과 창에 남습니다 |
| `CalculatorDrill.Apply(c, action)` | 걸음 하나를 기계에 적용합니다. WP22 시험 묶음이 같은 목록을 손동작으로 옮깁니다 |

### SlideRule · 계산자

위치는 자 길이(D 눈금 1~10)를 1로 둔 단위입니다. 값 v는 log10(v)에 있습니다.

| 멤버 | 하는 일 |
| --- | --- |
| `Slide` | C 눈금 왼쪽 기준이 D 눈금의 어디에 있는지(−1~1) |
| `Cursor` | 커서 선이 D 눈금의 어디에 있는지(0~1) |
| `D`, `C`, `CI` | 커서 선 아래 눈금 읽기. 커서가 슬라이드 밖이면 C와 CI는 NaN |
| `Position(v)`, `Mantissa(v, out exp)` | 눈금 위치와 가수. 눈금을 그릴 때 씁니다 |
| `Graduation(m)`, `ReadByEye(m)` | 눈금 한 칸(1~2: 0.01, 2~4: 0.02, 4~10: 0.05)과 그 1/5까지 둥근 읽기 |
| `CursorToD`, `CursorToC`, `SlideCToCursor`, `SlideCIToCursor`, `CursorToIndex` | 조작 한 걸음씩 |
| `Multiply(a, b)`, `Divide(a, b)`, `MultiplyByCI(a, b)` | 교범 순서 그대로의 계산. 소수점은 조작자가 어림으로 정하는 것을 지수의 합으로 대신합니다 |

### Nomogram · 계산 도표

`new Nomogram(new NomogramTuning(LeakK, BatteryCapacityWh, BatterySubmergeStartL))`로 만듭니다. 값은 `data/tuning.json`의 `water.leakK`, `battery.capacityWh`, `water.batterySubmergeStartL`입니다. 라이브러리는 sim을 모르므로 Godot 층이 sim의 튜닝에서 읽어 넘깁니다.

| 도표 (`Chart.Id`) | 왼쪽 눈금 | 오른쪽 눈금 | 가운데 눈금 |
| --- | --- | --- | --- |
| `LeakRate` (`leak`) | 수심 50~1500m | 누수 면적 0.1~30cm² | 누수량 L/분 = 60 × k × 면적 × √수심 |
| `BatteryHours` (`battery`) | 축전지 잔량 용량의 2%~100% Wh | 부하 20~2000W | 남은 시간 h = Wh ÷ W |
| `Submersion` (`submersion`) | 앞 빌지 수위 0L~(잠김 시작 − 10L) | 순유입 1~200L/분 | 잠길 때까지 분 = (잠김 시작 − 수위) ÷ 순유입 |

| 멤버 | 하는 일 |
| --- | --- |
| `Chart.Left`, `Middle`, `Right` | 눈금 세 줄. `X`(0, 가운데, 1), `Y(value)`, `ValueAt(y)`, `Point(value)`, `Ticks`, `Title`, `Unit` |
| `NomogramScale.Ticks` | 로그 눈금은 1~2에서 0.1, 2~5에서 0.2, 5~10에서 0.5 간격(1, 2, 5가 굵은 눈금). 빌지 수위는 5L 간격, 10L마다 숫자, 50L마다 굵은 눈금 |
| `Chart.Read(a, b)` | 자의 두 끝(도표 좌표, 어디든 좋다)을 넣으면 가운데 눈금에서 눈으로 읽은 값. 가는 눈금 간격의 1/5로 둥깁니다. 자가 세로로 서거나 눈금 끝에서 6mm보다 멀리 지나면 NaN |
| `Chart.CrossingY(a, b)` | 자가 가운데 눈금선을 지나는 높이 |
| `Chart.Solve(left, right)` | 공식으로 계산한 참값(시험과 교범 예시용) |

도표 좌표는 너비와 높이를 1로 둡니다. 눈금은 높이 0.05~0.95에 폅니다. 바깥 눈금의 기울기를 ma, mb라 하면 가운데 눈금은 x = ma/(ma+mb)에 서고, 자가 그곳을 지나는 높이는 log(결과)에 비례합니다. 부하와 순유입은 나누는 쪽이라 눈금이 위에서 아래로 커집니다.

### BridgeDials, BridgeBalance · 저항 측정 브리지

| 멤버 | 하는 일 |
| --- | --- |
| `new BridgeDials(decades = 4, ranges = {1, 1e3, 1e6})` | 10배 단위 다이얼 네 개와 범위 키 ×1, ×1k, ×1M |
| `Dial(i)`, `SetDial(i, d)`, `StepDial(i, steps)` | 다이얼 0이 맨 윗자리. 0과 9에서 멈춥니다 |
| `SetRange(i)`, `Range`, `Multiplier` | 범위 키 |
| `Reading`, `Ohms`, `Step` | 다이얼이 가리키는 정수, 설정 저항(정수 × 배율), 한 칸의 저항 |
| `BridgeBalance.Deflection(rx, dials)` | 검류계 바늘 −1~1. +는 Rx가 설정보다 크다(다이얼을 올려라). +∞(끊김)는 끝까지 +, 0(단락)은 끝까지 −, NaN(잴 수 없음)은 NaN |
| `BridgeBalance.Balance(rx, dials)` | 교범 순서의 평형 맞추기. 다이얼 수가 가장 많이 쓰이는 범위 키를 고르고, 맨 윗자리부터 바늘이 −로 넘어가기 직전까지 올립니다 |

브리지는 휘트스톤 회로를 그대로 풉니다. 비율 팔 P/Q = 범위 배율 M, 다이얼 저항 S, 평형이면 Rx = M × S입니다. 범위 키가 검류계 분로도 함께 바꾼다고 보고, 전위차에 (1+M)²/M을 곱해 범위마다 감도를 맞췄습니다. 그러면 평형 근처에서 바늘은 tanh(5 × ln(Rx ÷ 설정))쯤입니다. 10% 어긋나면 끝의 절반쯤 가고, 9999 근처에서 한 칸 어긋나면 거의 보이지 않습니다(실제 브리지와 같습니다).

## Godot에서 붙이는 법 (WP22)

공통 원칙:

- 장치의 상태는 Godot 노드가 이 라이브러리 객체를 하나씩 들고 있습니다. sim 명령이 아니고, 재생과 저장에 넣지 않습니다.
- 손동작은 M2 설계 'Gestures' 표를 따릅니다. **Dial**과 **DragPlane**은 장치 전용이고 명령을 보내지 않습니다.
- 브리지의 실제 저항만 sim에서 옵니다(`Measure(bridge, 대상)`, WP4).

### 탁상 계산기 (항법 책상)

| 부품 | 손동작 | 라이브러리 호출 |
| --- | --- | --- |
| 설정 레버 8개 | Dial (멈춤 0~9) | `StepLever(place, ±1)`. 레버 노치 위치는 `Lever(place)` |
| 손잡이 | Wheel, `TurnsPerFire` 1 | 시계 방향 한 바퀴 = `Forward()`, 반시계 = `Back()`. 돌 때마다 `noise.emit` 3을 0.4초 보냅니다(설계). 소리를 내는 명령은 이것 하나입니다 |
| 캐리지 옮김 단추 두 개 | Click | `ShiftUp()`, `ShiftDown()`. 캐리지 메시를 `Carriage` × 자리 간격만큼 옮깁니다 |
| 결과 창, 회전 수 창 | 보기만 | 숫자 바퀴마다 `ResultDigit(i)`, `CounterDigit(i)`. `CounterNegative`면 회전 수 숫자를 빨갛게 |
| 지우기 손잡이 세 개 | Click (또는 Lever 한 노치) | `ClearResult()`, `ClearCounter()`, `ClearSetting()` |
| 벨 | 소리 | `Bell` 사건에 작은 종소리를 붙입니다 |

시험 묶음 `instruments`(InstrumentSuite)는 `CalculatorDrill.Multiply(new DeskCalculator(), 123456, 789)`가 돌려준 `CalcAction` 목록을 손동작으로 옮깁니다. Set은 Dial, Shift는 Click, Forward와 Back은 Wheel 한 바퀴, Clear는 Click입니다. 끝난 뒤 장치의 `Result`, `Counter`를 라이브러리 결과와 비교합니다. 나눗셈은 벨에 반응해야 하므로 목록을 그대로 따르면 됩니다(목록이 이미 벨 뒤의 되돌림을 담고 있습니다).

### 계산자 (항법 책상 작업 시점)

| 부품 | 손동작 | 라이브러리 호출 |
| --- | --- | --- |
| 슬라이드 | 가로 Lever (노치 없이 연속), 또는 한 축에 묶은 DragPlane | `Slide = 끈 거리(m) ÷ 자 길이(0.25m)` |
| 커서 | 가로 Lever 연속 | `Cursor = 거리 ÷ 0.25m` |
| 눈금 그리기 | 절차적 | 눈금 위치는 `Position(v)`(C, D는 그대로, CI는 1 − Position). 눈금 간격은 `Graduation(m)` |

읽기는 플레이어가 눈으로 합니다. 시험 묶음은 `D`, `C`, `CI`로 확인하고, 설계대로 1% 안을 봅니다.

### 노모그램 도표 (항법 책상 벽)

| 부품 | 손동작 | 라이브러리 호출 |
| --- | --- | --- |
| 도표 세 장 | 보기만 | 눈금선은 `scale.X`, 눈금은 `scale.Ticks`(Y, Major, Label). 도표 좌표 × 실제 너비·높이 |
| 자의 두 끝 | DragPlane 두 개 | 끝 위치를 도표 좌표 `ChartPoint`로 바꿉니다(왼쪽 아래가 0, 너비·높이로 나눔) |
| 자 아래 표시 | 보기만 | 자가 가운데 눈금을 지나는 곳은 `CrossingY(a, b)`. 확대 보기에서 그 자리를 보여 줍니다 |

`Read(a, b)`는 화면에 숫자로 띄우지 않습니다(화면 UI 최소, SPEC 7절). 시험 묶음이 자 끝을 `Left.Point(값)`, `Right.Point(값)`에 놓고 읽어 설계대로 3% 안을 봅니다. 튜닝은 `NomogramTuning(t.Water.LeakK, t.Battery.CapacityWh, t.Water.BatterySubmergeStartL)`로 넘깁니다. 튜닝이 바뀌면 눈금이 저절로 다시 만들어집니다.

### 저항 측정 브리지 (통신 책상)

| 부품 | 손동작 | 라이브러리 호출 |
| --- | --- | --- |
| 리드 선택기 12칸 | Lever (노치 12) | 장치 상태. 잴 대상(시험 리드 A/B, 분기함 C1~C8, 상황판 배선, 케이블 단자)을 고릅니다. 라이브러리는 모릅니다 |
| 범위 키 ×1, ×1k, ×1M | Click | `SetRange(i)` |
| 10배 단위 다이얼 네 개 | Dial (멈춤 0~9) | `StepDial(i, ±1)` |
| 누름 키 | Probe (누르고 있는 동안) | 매 프레임 `Deflection(Measure(bridge, 대상), dials)`. 바늘 각도 = 편향 × 최대 각. 감쇠는 Godot에서 줍니다. 키를 놓으면 바늘은 0으로 돌아옵니다 |
| 검류계 | 보기만 | 편향이 NaN이면(스위치를 켠 채 절연을 잼) 바늘을 떨게 합니다. 케이블 단자(M3)는 +∞라 끝까지 +로 갑니다 |

시험 묶음은 `BridgeBalance.Balance(Measure(...), new BridgeDials())`가 고른 범위 키와 다이얼을 Click과 Dial로 옮기고, 장치 바늘이 다이얼 한 칸 안에서 부호를 바꾸는지 봅니다.

> # 계산 도구
>
> 항법 책상에 탁상 계산기, 계산자, 벽의 계산 도표가 있다. 통신 책상에 저항 측정 브리지가 있다. 계산이 빨라야 하면 계산자와 도표를, 정확해야 하면 계산기를 쓴다.
>
> ## 탁상 계산기
>
> - 설정 레버 8개로 수를 놓는다. 오른쪽 끝이 일의 자리다.
> - 손잡이를 앞으로 한 바퀴 돌리면 놓은 수가 결과 창에 더해진다. 뒤로 돌리면 빠진다.
> - 회전 수 창은 손잡이를 몇 번 돌렸는지 센다. 뒤로 돌린 것이 더 많으면 숫자가 붉다.
> - 캐리지를 왼쪽으로 한 칸 옮기면 한 바퀴가 열 배가 된다.
> - 빼서 결과가 0 아래로 내려가면 벨이 울린다. 결과 창은 9로 가득 찬다. 앞으로 한 번 돌리면 돌아온다.
> - 손잡이는 한 바퀴마다 소리가 난다. 조용히 해야 할 때는 계산자를 쓴다.
>
> ### 곱하기: 123456 × 789
>
> 1. 지우기 손잡이 세 개를 모두 당긴다. 캐리지를 오른쪽 끝에 둔다.
> 2. 레버에 123456을 놓는다.
> 3. 곱하는 수의 일의 자리 9만큼 손잡이를 앞으로 돌린다.
> 4. 캐리지를 왼쪽으로 한 칸 옮기고, 십의 자리 8만큼 돌린다.
> 5. 캐리지를 한 칸 더 옮기고, 백의 자리 7만큼 돌린다.
> 6. 결과 창에 97406784, 회전 수 창에 789가 있다. 회전 수가 곱하는 수와 같은지 보고 확인한다.
>
> ### 나누기: 1234 ÷ 6.5 (케이블 고장 거리, M3 예고)
>
> 소수 둘째 자리까지 원하면 나뉘는 수에 0을 두 개 더 붙인다고 생각한다. 나누는 수의 소수점은 떼고 그만큼 나뉘는 수에도 0을 붙인다.
>
> 1. 지우기 손잡이 세 개를 모두 당긴다.
> 2. 레버에 1234를 놓는다. 캐리지를 왼쪽으로 세 칸 옮긴다(소수 둘째 자리 둘, 6.5의 소수점 하나). 손잡이를 앞으로 한 번 돌린다. 결과 창에 1234000이 올라간다.
> 3. 회전 수 창만 지운다. 레버를 지우고 65를 놓는다.
> 4. 65의 맨 윗자리가 결과 창 맨 윗자리 아래에 오도록 캐리지를 옮긴다(여기서는 다섯째 칸에서 시작한다. 그 자리에서 한 번도 못 빼면 벨이 바로 울리고, 그래도 괜찮다).
> 5. 벨이 울릴 때까지 손잡이를 뒤로 돌린다.
> 6. 벨이 울리면 앞으로 한 번 돌려 되돌리고, 캐리지를 오른쪽으로 한 칸 옮긴다.
> 7. 캐리지가 오른쪽 끝에 닿을 때까지 5와 6을 되풀이한다.
> 8. 회전 수 창의 붉은 숫자 18984가 몫이다. 소수점은 뒤에서 두 자리: 189.84km. 결과 창에 남은 수는 나머지다.
>
> 다른 공식:
>
> - 항법 계산기의 거리 = 축 회전 수 × 한 바퀴에 나아가는 거리. 4812회 × 1.85m라면 4812 × 185 = 890220, 소수점 두 자리를 떼서 8902.2m, 곧 8.90km.
> - 남은 시간 = 남은 양 ÷ 쓰는 빠르기. 시간 = Wh ÷ W, 분 = 남은 빌지 L ÷ 순유입 L/분.
>
> ## 계산자
>
> - D 눈금은 몸체에, C 눈금은 슬라이드에, CI 눈금(거꾸로 된 C)은 슬라이드 가운데에 있다.
> - 세 자리쯤 읽힌다. 1과 2 사이는 0.01, 2와 4 사이는 0.02, 4부터는 0.05가 한 칸이다.
> - 소수점은 계산자가 알려 주지 않는다. 어림으로 정한다.
>
> ### 곱하기: 2.4 × 3.7
>
> 1. 커서를 D의 2.4에 맞춘다.
> 2. 슬라이드를 밀어 C의 왼쪽 1을 커서 선에 맞춘다.
> 3. 커서를 C의 3.7로 옮긴다.
> 4. 커서 아래 D를 읽는다: 8.88.
> 5. C의 3.7이 몸체 밖으로 나가면 2에서 C의 오른쪽 10을 맞추고, 읽은 수에 10을 곱한다.
>
> ### 나누기: 120 ÷ 62
>
> 1. 커서를 D의 1.2에 맞춘다.
> 2. 슬라이드를 밀어 C의 6.2를 커서 선 아래로 가져온다.
> 3. 커서를 C의 1이나 10 중 몸체 위에 있는 쪽으로 옮기고 D를 읽는다: 1.936.
> 4. 어림: 120 ÷ 60은 2쯤이다. 답은 1.94다.
>
> ## 계산 도표
>
> 항법 책상 벽에 도표 세 장과 자가 있다. 자를 왼쪽 눈금의 값과 오른쪽 눈금의 값에 대면, 자가 가운데 눈금을 지나는 곳이 답이다. 2% 안에서 맞는다.
>
> ### 도표 1. 수심별 누수량
>
> 공식: 누수량(L/분) = 60 × 0.02 × 면적(cm²) × √수심(m).
>
> - 수심 300m, 리벳 하나가 다 빠짐(3cm²): 자를 수심 300과 면적 3에 댄다. 가운데에서 62L/분을 읽는다.
> - 같은 수심에서 0.5cm²만 새면 10.4L/분이다.
>
> ### 도표 2. 축전지 남은 시간
>
> 공식: 남은 시간(시간) = 잔량(Wh) ÷ 부하(W). 꽉 찬 축전지는 1200Wh다.
>
> - 반쯤 남음(600Wh), 펌프와 팬과 조명으로 400W: 자를 600과 400에 댄다. 1.5시간.
> - 부하 눈금은 위로 갈수록 작다. 장비를 끄면 자의 오른쪽 끝이 올라가고 답이 커진다.
>
> ### 도표 3. 축전지가 잠길 때까지
>
> 공식: 남은 분 = (240 − 앞 빌지 수위 L) ÷ 순유입 L/분. 순유입은 새어 드는 양에서 펌프가 퍼내는 양을 뺀 것이다. 앞 빌지가 240L에 닿으면 셀이 잠기기 시작하고 염소가 나온다.
>
> - 도표 1에서 10.4L/분을 읽었다. 펌프가 멈췄다. 앞 빌지 유리관이 120L를 가리킨다.
> - 자를 수위 120과 순유입 10.4에 댄다. 11.5분쯤.
> - 그 안에 펌프를 살리거나 수동 펌프를 잡는다.
>
> ## 저항 측정 브리지
>
> - 통신 책상에 있다. 리드 선택기, 범위 키 세 개(×1, ×1k, ×1M), 다이얼 네 개, 누름 키, 검류계가 있다.
> - 잴 것을 고르고, 다이얼을 돌리고, 누름 키를 누른 채 바늘을 본다.
> - 바늘이 오른쪽(+)이면 다이얼을 올리고, 왼쪽(−)이면 내린다.
> - 바늘이 0에 서면 저항 = 다이얼 네 자리 × 범위 키.
> - 분기함 절연은 그 회로의 스위치를 내리고 잰다. 스위치가 올라가 있으면 바늘이 떨기만 한다.
>
> ### 재기: C3 분기함 절연
>
> 1. 배전반에서 C3 스위치를 내린다.
> 2. 리드 선택기를 C3에 놓는다. 범위 키 ×1M을 누른다.
> 3. 누름 키를 누른다. 다이얼이 모두 0이면 바늘이 오른쪽 끝으로 간다.
> 4. 맨 왼쪽 다이얼부터 한 칸씩 올린다. 바늘이 왼쪽으로 넘어가면 한 칸 되돌리고 다음 다이얼로 간다.
> 5. ×1M에서 맨 오른쪽 다이얼을 1에 놓아도 바늘이 왼쪽으로 가면 1MΩ보다 작다. 범위 키를 ×1k로 바꾸고 다시 한다.
> 6. 예: ×1k에서 0050 → 50kΩ, 곧 0.05MΩ. 08쪽 표로 보면 젖었다(1MΩ 아래).

## 정한 것 (사람에게 묻지 않고 추천 기본값으로)

1. **시험 위치.** `instruments/DeepLine.Instruments.Tests`에 따로 둡니다. 설계안 WP21의 `sim.tests/InstrumentTests.cs`는 만들지 않았습니다(본선 충돌 회피, 이번 지시). WP23에서 설계 파일 목록을 고치면 됩니다.
2. **계산기 크기.** 설정 8, 결과 13, 회전 수 8자리. 캐리지는 0~5자리라서 곱하는 수는 여섯 자리까지, 곱은 13자리까지입니다. 오드너 7형쯤의 크기입니다.
3. **벨은 빼서 0 아래로 내려갈 때만.** 더해서 13자리를 넘치면 조용히 돕니다(실제 기계도 넘침에는 종이 없습니다).
4. **나눗셈의 몫은 붉은 숫자.** 뒤로 돌린 것이 회전 수에 −로 쌓여서, 몫은 회전 수 창에 붉은 숫자로 나옵니다(브룬스비가식). 교범 초안이 그렇게 적습니다.
5. **계산자 정밀도.** 25cm 만하임식 눈금, 입력과 결과 모두 눈금 한 칸의 1/5까지 읽는다고 봅니다. 세 번 둥글어도 0.5% 안입니다.
6. **노모그램 읽기.** `Read`는 가는 눈금 간격의 1/5로 둥근 값을 돌려줍니다. 눈금 끝에서 6mm(도표 높이의 1%)까지는 읽고 그보다 멀면 NaN입니다.
7. **노모그램 범위.** 수심 50~1500m, 누수 면적 0.1~30cm², 잔량은 용량의 2%~100%, 부하 20~2000W, 순유입 1~200L/분. 수위 눈금은 0L부터 잠김 시작 10L 전까지입니다. 축전지 잔량은 %가 아니라 Wh로 둡니다(설계 'battery hours from Wh and load'). 계기에 %로 나온다면 WP22에서 같은 눈금 옆에 % 눈금을 덧그리면 됩니다(위치는 `Y(용량 × 비율)`).
8. **도표 3의 빌지.** 축전지가 있는 앞 빌지(`water.batteryBilge`)의 수위만 씁니다. 해치를 열어 두면 두 빌지가 고르게 차므로 실제로는 더 늦게 잠깁니다. 교범 문장으로 다룹니다.
9. **브리지.** 다이얼 네 개, 범위 키 ×1·×1k·×1M(설계 그대로). 바늘 감도는 범위마다 같게 맞추고, 10% 어긋나면 끝의 절반쯤 갑니다. 끊김(+∞)은 +끝, 단락은 −끝, 잴 수 없음(NaN)은 NaN입니다.
