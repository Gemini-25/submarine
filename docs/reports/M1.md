## 구현한 것

### 시뮬레이션 (`sim/`)

- **자유형 손 수리** (`sim/Repair/HandActions.cs`). 화면에 단계 안내가 없고, 시뮬레이션이 물체 상태와 행동마다의 전제 조건으로 판정합니다.
  - 퓨즈: 뽑기, 꽂기, 폐기함에 버리기, 사물함에서 꺼내기.
  - 흡입 거름망: 볼트 4개 풀고 조이기, 덮개 열고 닫기, 바구니 빼고 넣기, 세척통에서 솔질.
  - 리벳 이음: 나무망치로 쐐기 박기, 버팀목 대기, 코킹.
- **위험.** 살아 있는 퓨즈 소켓을 만지면 감전(불꽃, 수소가 있으면 폭발), 펌프가 도는 채로 바구니를 빼고 넣으면 끼임. 둘 다 숨은 체력을 깎고 잠시 손을 못 쓰게 합니다. 거듭되면 쓰러져 실패.
- **숨은 결함.** 볼트가 하나라도 풀려 있으면 공기가 새어 배수량이 줄고, 바구니 없이 돌리면 베어링이 빨리 닳습니다.
- **임무 스크립트** (`data/missions/m1-crisis.json`). 수심 300m에서 흡입구 막힘(0초) → 후방 리벳 09 누수(20초) → C3 퓨즈 단선(60초). 다 고치고 빌지를 60L 아래로 1분 유지하면 성공, 25분 제한.

### 교범 (`data/manual/`, 10쪽)

개요와 배치, 계통 상황판, 진단 표, 절차 4개(퓨즈 교체, 펌프 흡입 거름망 청소, 리벳 이음 응급 막기, 리벳 이음 코킹), 침수 대응, 공기와 몸 상태, 소음 표. 게임 안에서는 Tab으로 펴고, 첫 장은 이번 임무의 지시서, 마지막 장은 조작 안내입니다. 모든 수치는 코드와 데이터에 대조했습니다.

### Godot (`game/`)

- **회색 상자 모스호.** 세 구역과 해치, 전방 끝벽의 계통 상황판(표시등 8, 계기 8, 경보 벨), 구역 경고등, 중앙 우현 배전반(칼날 스위치, 퓨즈 소켓, 부하 단자, 회로 표시등, 버스 바), 중앙 좌현 예비품 사물함과 폐기함과 수동 펌프, 후방의 전동 펌프와 흡입 거름망과 세척통, 리벳 이음 12곳(물줄기와 쉿 소리), 전방 바닥 아래 축전지 우물(격자 너머로 셀과 물이 보임), 빌지 수위 유리관 두 개.
- **조작.** WASD와 마우스, Ctrl 웅크리기, 오른쪽 버튼 가까이 보기, F 작업 시점(배전반, 거름망, 사물함, 상황판), 1~6 도구, Tab 교범, N 메모장, F1 조작 안내, R 다시 시작.
- **화면.** 조준점과 물체 이름, 든 것, 거부되었을 때 '손이 느낀 결과' 한 줄. 몸 상태는 숫자 없이 흐림, 시야 축소, 누런 기운, 번쩍임, 어두워짐으로.
- **빛.** 실내등은 버스 전압에 비례하고 전압이 낮으면 깜빡임. 구역 경고등은 상황판과 별개.
- **소리 (자리표시 합성음).** 펌프와 팬 회전음, 흡입구 자갈, 역류, 풀린 볼트로 공기 새는 소리, 누수 지점마다 3D 쉿 소리, 경보 벨, 손동작 소리, 숨소리.
- **개발 도구 (디버그 빌드).** F3 값 보기, F4 명령 창, F5 멈춤, F6 시간 배율.

결정 사항은 [docs/DECISIONS.md](../DECISIONS.md)의 'M1' 절에 있습니다.

## 실행과 플레이

1. Godot 4.7.2 **.NET** 판으로 `game/project.godot`를 엽니다. 처음 열면 글꼴을 가져오고, 편집기 오른쪽 위의 빌드 버튼으로 C#을 빌드합니다.
2. F5로 실행하면 지시서가 뜹니다. Enter나 클릭으로 근무를 시작합니다.
3. 막히면 Tab으로 교범을 봅니다. 조작은 교범의 마지막 장 '조작 안내'에 있습니다.

명령줄 확인:

```sh
dotnet test
GODOT=/경로/Godot_v4.7.2-stable_mono_linux.x86_64 tools/godot-check.sh
```

## 리뷰

M1 전체를 다섯 관점(시뮬레이션, Godot, 교범을 든 플레이어, 명세 적합성, 테스트 품질)으로 리뷰하고, 관점마다 따로 반박 검증을 거쳤습니다. 36건 중 24건이 확인되어 모두 고쳤습니다. 기각된 12건 중에서도 고치는 비용이 작은 것은 보강으로 넣었습니다.

**플레이어에게 보이던 결함:**
- 위기를 넘겨도 결과 화면이 '임무 실패'로 뜨고 실패 사유가 비어 있었다. 사건을 알릴 때 상태가 한 틱 늦었다.
- 성공한 뒤에도 시간이 흘러, 결과 화면을 띄워 둔 채 오래 두면 실패로 뒤집혔다. 이제 성공과 실패는 최종이고 결과 화면에서 시간이 멈춘다.
- 나무망치를 든 채 버팀목을 쥐고 이음새를 누르면 쐐기 치기가 되어 버팀목을 댈 수 없었다. 교범대로 해도 위기를 못 넘기는 경로였다. 이제 쥔 물건이 먼저다.
- Esc로 마우스를 푼 뒤 클릭하면 조준선 위 물체(살아 있는 퓨즈 등)를 건드렸다. 이제 시선만 다시 잡는다.
- 거름망 덮개를 끌 때 움직임이 반대로 보였다.
- 임무가 끝날 때 교범이 펴져 있으면 결과 화면이 가려졌다.
- 다 고친 뒤 C3 스위치를 내리면 이유 없이 실패했다. 성공 조건에서 '펌프가 돌 것'을 뺐다.
- 코킹을 마쳐도 미세 누수로 쉿 소리와 물줄기가 남아 교범의 확인 방법과 어긋났다. 코킹은 이제 새것처럼 메운다.

**테스트 구멍:** 리뷰어가 넣어 본 변이가 모든 테스트를 통과하던 곳들이다.
- 시뮬레이션 테스트 19개를 더했다. 끊긴 퓨즈를 스위치를 올린 채 뽑을 때의 감전, 끊긴 퓨즈 도로 꽂기, 덜 닦은 바구니, 손을 못 쓰는 시간, 제한 시간, 저장 뒤 남은 고장 주입, 유지 시간의 정확성과 초기화, 교범의 전제 조건 표, 코킹 횟수, 절차 횟수와 튜닝과 교범의 일치를 본다. 위기 한 판도 기준 해시로 기록한다.
- Godot 종단 테스트에 결과 화면 제목, 해치를 걸어서 지나가기, 코킹 손동작, 펌프가 도는 채 바구니 빼기(끼임)를 더했다.
- 변이 다섯 개를 다시 넣어 새 테스트가 잡는 것을 확인했다.

**작은 보강 (검증에서 기각되었지만 넣은 것):**
- 배전반에 회로마다 표시등을 달았다. 끊긴 회로를 눈으로 찾을 수 있다.
- 실내등 밝기를 전압에 정비례로 바꿨다.
- 거부된 손동작은 소리를 내지 않는다.
- 저장 형식에 사물함 길이 검사를 넣었다.
- 유지 시간 0인 임무 데이터를 거부한다.
- 성공 조건에 '바구니가 들어 있을 것'을 넣었다.
- 수위 유리관 이름을 교범과 같게 '전중 빌지'로 고쳤다.
- 디버그 명령 창의 다시 시작이 게임의 다시 시작과 같은 정리를 한다.

## 알려진 문제

- **조작감은 확인하지 못했습니다.** 손동작의 거리(끌기 140픽셀, 원 반지름 60픽셀, 볼트 1.5바퀴)와 마우스 감도는 짐작값입니다.
- **소리는 들어 보지 못했습니다.** 합성음이 헤드리스와 가상 화면에서 오류 없이 도는 것만 확인했습니다. 음색은 M5에서 다시 만듭니다(병렬 세션이 미리 준비 중).
- **물체 이름표.** 조준한 물체의 이름과 손동작 이름을 화면에 띄웁니다. 회색 상자 단계의 편의라서 M5에서 다시 봅니다.
- **바닥 아래로 기어 들어가는 공간이 없습니다.** 웅크리기는 낮은 곳을 가까이 보는 데만 쓰입니다. M2에서 케이블 챔버와 함께 넣습니다.
- **`m0` 태그를 원격에 올리지 못했습니다.** 이 세션은 작업 브랜치에만 푸시할 수 있어서 태그 푸시가 HTTP 403으로 거부됩니다. 로컬에는 75b943d에 있습니다. GitHub에서 직접 붙여 주세요.
- **플랫폼 간 결정론은 아직 Linux x64에서만 확인했습니다** (M0와 같음).
